# Kallisto 1.1.0

## Goals (in this minor release)

- `kallisto_config.yaml` hoặc `.toml`
- Chia tách rõ hai chế độ qua config flag (`role: sovereign | proxy`)
- State machine: Seal trait + Transit backend
- Encryption barrier
- Module storage backend mới với redb (đã có Hexagonal port)


## Non-goals (later - need to place in roadmap)

- Raft / clustering cho control plane
- Foca gossip cho Data Plane
- Terraform provider cho Control Plane để provisioning

## Visible changes

- config: thêm `role:`, thành bắt buộc
- breaking: file config cũ không parse được nữa

## Work items

1. Config schema tagged-enum → brief 01, ADR-0011
2. Seal trait → brief 02, ADR-0004
3. Barrier + buffer pool → brief 03, ADR-0012

## Nghiệm thu

- cargo test --workspace 100% pass rate
- bench-laptop giữ trong 10% của baseline 1.386ms
- validate reject được config sai role

## Khuyến nghị

Làm proxy mode trước, và để chế độ sovereign lại cho tới khi có người dùng thật hỏi xin nó. 

Nên làm proxy mode trước vì nó không hy sinh gì cả. Nó là con đường ngắn nhất tới một thứ hoàn chỉnh, và cũng là con đường tới chế độ sovereign. Hơn nữa, ~70% code dùng chung: engine, HTTP, cuckoo table, auth, barrier. 

Encryption barrier cần ở cả hai chế độ, chỉ khác chỗ nó bảo vệ: proxy thì bảo vệ RAM, standalone thì bảo vệ đĩa.

# Implementation Roadmap (v1.1.0)

Dựa trên các quyết định thiết kế từ tập ADR (ADR-0001 đến ADR-0011), dưới đây là lộ trình và thứ tự ưu tiên triển khai (Tasks) cho phiên bản 1.1.0:

## Phase 1: Foundation & Scaffolding
1. **Phân rã kiến trúc (ADR-0005)**: Thiết lập hệ thống build/features để tách biệt rạch ròi `controlplane` và `dataplane`.
2. **Cấu hình mới (ADR-0003)**: Cài đặt parser cho định dạng cấu hình YAML hợp nhất.

## Phase 2: Storage & Concurrency (Sovereign/Hybrid Mode)
3. **Storage Engine (ADR-0009)**: Triển khai trait `RaftLogStorage` của `openraft` sử dụng `redb` (3 bảng: log, state, meta).
4. **Group Commit Async (ADR-0008)**: Tích hợp hàng đợi lock-free Vyukov MPMC và luồng flusher (`oneshot` channel callback) để ghi đĩa không block Tokio executor.

## Phase 3: Proxy Mode (Data Plane)
5. **Zero Persistence (ADR-0001 & ADR-0011)**: Loại bỏ hoàn toàn ghi đĩa, sử dụng in-memory arena, nạp cấu hình từ ConfigMap, cấu hình Node ID bằng `/etc/machine-id`.
6. **Kiểm soát bộ nhớ & Log (ADR-0011)**: Cài đặt giới hạn cgroup cho Arena và cơ chế hash (băm) secret path trong log để tránh rò rỉ.
7. **Cache & Fallback (ADR-0011)**: Cài đặt cơ chế Fail-open (upstream sập thì trả dữ liệu cũ) và Fail-closed (mất JWKS thì từ chối auth).

## Phase 4: Control Plane, Network & Policies
8. **Loopback Identity Auth (ADR-0006)**: Phát triển cơ chế HTTP Loopback auth và cấp phát Scoped Token cho các workload cục bộ.
9. **Chính sách bí mật tĩnh (ADR-0010)**: Hiện thực luồng kiểm tra logic để đảm bảo Sovereign luôn hoạt động như kho chứa, không tự sinh credential động (Atomic Handoff).

## Phase 5: Integration & UX
10. **Terraform Provider (ADR-0007)**: Phát triển provider với resource `kallisto_secret_wo` (write-only) để tự động hóa hạ tầng (Zero Ceremony) không rò rỉ secret vào state file.
11. **Giao diện (ADR-0004)**: Tích hợp WebUI/TUI cho việc giám sát trạng thái Control Plane.
